Quick Start & Setup

Integrate eLegal's powerful research engine into your own applications using our REST API. Follow these guidelines to establish a connection:

1. Authentication: Pass your generated API key in the headers of every request as X-API-Key: your_key_here. Unauthorized requests will be rejected with a 401 status.

2. Base URL: When running the eLegal server, all endpoints are relative to your active domain host, typically http://localhost:3000.

3. Rate Limiting: To ensure local engine stability, requests are limited to 100 per minute per IP address. Exceeding this returns a 429 Too Many Requests status.

4. Responses: All API responses are returned as standard JSON. In the event of a failure, the payload will include a status and detailed message field.

SETUP

Environment & Architecture Overview

eLegal provides a high-throughput legal search engine and document resolver. Every protected endpoint requires a valid X-API-Key header or Firebase Authorization token. API keys are generated per authenticated user UID, saved in Firestore under apikeys/{userId}/keys/{key}, and stored with local AES-256-GCM encryption in the application server database for sub-millisecond key validation without Firestore latency spikes.

Base URL: http://localhost:3000

Authentication Headers: X-API-Key: el_... for data endpoints, Authorization: Bearer <Firebase_ID_Token> for key management.

GUIDE

Response Codes & Error Handling

eLegal returns standardized HTTP response codes and consistent JSON payloads for all requests. Applications should inspect the HTTP status code and parse the returned error or message property when non-200 responses occur.

HTTP 200 OK Success

Request executed successfully. Returns the requested JSON dataset or document structure.

HTTP 400 Bad Request Invalid Parameters

Missing mandatory query parameters (e.g., omitting q in search or sourceUrl in document-content).

{ "error": "Query parameter 'q' is required for search" }
HTTP 401 Unauthorized Authentication Failed

Missing or invalid X-API-Key header, or inactive/revoked API key.

{ "error": "Unauthorized", "message": "Valid X-API-Key header required" }
HTTP 429 Too Many Requests Rate Limited

Request quota exceeded (>100 requests per 60-second sliding window per API key).

{ "error": "Rate limit exceeded. Try again in 42 seconds.", "retryAfter": 42 }

Production Code Examples & Error Handling

Below are production-ready code patterns for integrating eLegal into modern Node.js/TypeScript applications, Python scripts, and shell automation scripts with built-in retry logic and error validation.

Node.js / TypeScript Instance with Robust Error Handling & Retry

TypeScript / Node.js Client 
import fetch from 'node-fetch';

interface SearchResult {
  title: string;
  citation: string;
  url: string;
  type: 'precedent' | 'statute';
  source: 'kenya' | 'international';
  excerpt: string;
}

async function searchLegalCorpus(query: string, apiKey: string, retries = 3): Promise<SearchResult[]> {
  const endpoint = `http://localhost:3000/api/search?q=${encodeURIComponent(query)}&source=all`;

  for (let attempt = 1; attempt <= retries; attempt++) {
    try {
      const res = await fetch(endpoint, {
        method: 'GET',
        headers: {
          'Accept': 'application/json',
          'X-API-Key': apiKey
        }
      });

      if (res.status === 429) {
        const delay = attempt * 2000;
        console.warn(`[Rate Limited] Waiting ${delay}ms before retry ${attempt}...`);
        await new Promise(r => setTimeout(r, delay));
        continue;
      }

      if (!res.ok) {
        const errData = await res.json().catch(() => ({}));
        throw new Error(`API Error (${res.status}): ${errData.error || errData.message || res.statusText}`);
      }

      return await res.json();
    } catch (err) {
      if (attempt === retries) throw err;
    }
  }
  throw new Error('Max retries exceeded');
}

Python Instance with Exception Handling

Python Client 
import requests
import time

def get_document_content(source_url, api_key):
    endpoint = "http://localhost:3000/api/document-content"
    headers = {
        "Accept": "application/json",
        "X-API-Key": api_key
    }
    params = { "sourceUrl": source_url }

    try:
        response = requests.get(endpoint, headers=headers, params=params, timeout=15)
        
        # Handle HTTP error status codes
        if response.status_code == 401:
            raise PermissionError("Invalid or inactive API key provided.")
        elif response.status_code == 429:
            print("Rate limit reached. Pausing requests...")
            time.sleep(5)
            return get_document_content(source_url, api_key)
            
        response.raise_for_status()
        return response.json()
        
    except requests.exceptions.RequestException as e:
        print(f"Network or server error occurred: {e}")
        return None

KEY API

API Key Management (/api/keys)

Endpoints for managing developer API keys. Requires a Firebase User ID token in the Authorization header (Authorization: Bearer <Token>).

POST /api/keys

Generates a new API key. Encrypts and syncs with Firestore and local database store.

GET /api/keys

Lists all API keys created under the authenticated user UID.

PATCH /api/keys/:keyId

Updates key label or toggles isActive status.

DELETE /api/keys/:keyId

Permanently deletes an API key and purges local and Firestore caches.

GET /api/health
